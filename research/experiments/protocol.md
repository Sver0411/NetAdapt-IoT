# 实验协议

版本：固定四 slot 预算桶模型。记录日期：2026-11-06。

## 实验矩阵

15 场景 × 20 个 seed（100–119）× 13 方法，共 3,900 次运行。每次 4,000 slots，warmup 为 500 slots；默认 dt=0.1 s。开发配置使用 seeds 0、1，共 52 次运行。

| 类型 | 参数 | 观察目标 |
|---|---|---|
| 正常负载 | rate=0.015/slot | 日常业务表现 |
| 高负载 | rate=0.10/slot | 拥塞下的服务取舍 |
| 设备数量 | 8/24/48/96 逻辑设备 | 总需求与队列竞争 |
| 异频率 | 0.25/1/2 倍率 | 高频与低频流的分配 |
| 优先级 | 等权重配置 | 权重机制影响 |
| 链路质量 | p=0.95、0.55、二态 Markov | 交付与公平性 |
| 突发 | 每 400 slots 中 80 slots 四倍流量 | 短时拥塞与恢复 |
| 资源预算 | duty=0.4/0.8/1 | 服务机会变化 |
| 传播延迟 | delay=5 | 在途包与反馈时间 |
| 包长 | 64/128 B | 非抢占服务成本 |
| 消融 | 分别去除 FUD 三项 | 分量贡献 |

全部场景统一 bucket_slots=4。完整参数见[study.json](../../configs/study.json)。

## 配对条件

每个 seed 预生成到达、信道状态和潜在成功结果。各算法共享同一绝对时刻与业务流索引的随机场、队列规则和资源预算；发送时刻决定实际使用的信道结果。

每次运行保存配置、trace/source hash、seed、环境版本、逐包状态、调度决策和每流统计。

## 指标与统计

事件使用 warmup≤generation<T−guard 的生成 cohort；背景流量持续到观察终点。guard 覆盖截止期、最大服务时间和传播延迟。状态 AoI 在 warmup 后按 slot 边界积分。

按 seed 计算 FUD 相对基线的配对差值，固定分析 seed=20261106，进行 2,000 次 bootstrap 并给出 95% CI。全部比较属于探索性分析。summary.csv、paired_differences.csv 与 negative_results.csv 分别保存汇总、完整配对和不利均值方向。

运行器检查包守恒、单服务器占用、累计预算和时间戳顺序，运行状态写入 completion.json 与 failures.json。

## 物理实验计划

PC 队列调度多逻辑流，经 ESP32 A/E220 发送至 ESP32 B/E220，由接收端回复 ACK。先完成单帧与事务时序校准，再按配置重放业务负载。每种方法轮换顺序并重复测量，保存环境和双端日志。
